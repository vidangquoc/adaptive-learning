# Challenge Extraction

Challenge Extraction is the process of identifying concrete assessment tasks in learning material and turning them into Challenge Candidates.

The primary source of a source-derived Challenge is the assessment task already present in the source, especially individual items within exercises.

Challenge Extraction is therefore an extraction process, not a process that generates assessment tasks from Knowledge Atoms.

## Relationship to Source

A source may contain exercises with one or more concrete assessment tasks.

For example:

```
Exercise 3: Choose the correct answer.

1. I ___ to London last year.
   A. have gone
   B. went
   C. have been
   D. go

2. Have you ever ___ sushi?
   A. eat
   B. ate
   C. eaten
   D. eating
```

The extraction process should identify the individual assessment tasks:

```
Source
  ↓
Exercise
  ↓
Exercise Item
  ↓
Challenge Candidate
```

Each extracted item represents a candidate for a concrete Challenge.

## Extraction, Not Generation

Challenge Extraction should preserve the distinction between an assessment task that already exists in the source and a new task generated by the system.

For source-derived Challenges:

```
Source
  ↓
Exercise
  ↓
Assessment Task
  ↓
Challenge Extraction
  ↓
Challenge Candidate
```

Knowledge Atoms are not required as input to this extraction process.

Knowledge Atom extraction and Challenge extraction are separate concerns:

```
                    ┌─→ Knowledge Atom Candidates
Source / Segment ───┤
                    └─→ Challenge Candidates
```

A later process may link a Challenge Candidate to a Knowledge Atom.

## What Should Be Extracted?

The extraction process should identify the information needed to reconstruct the concrete assessment task and preserve its provenance.

Potential information includes:

- the task or prompt;
- the individual exercise item;
- available options or matching elements;
- answer information when provided by the source;
- instructions that apply to the item;
- the exercise context needed to interpret the item;
- source and segment provenance;
- the original form of the task where preservation is important.

The exact Challenge Candidate schema is not defined here yet.

## Individual Exercise Items

An exercise may contain multiple assessment tasks.

The extraction process should normally operate at the level at which a learner would perform a distinct task.

For example, a multiple-choice exercise containing ten numbered items should normally produce ten Challenge Candidates rather than one Candidate representing the entire exercise.

However, some source exercises may contain compound or interdependent tasks. Determining the correct extraction boundary is an unresolved design question.

## Challenge and Knowledge Atom Linking

Challenge extraction does not require Knowledge Atoms.

After extraction, a separate process can determine which Knowledge Atom a Challenge Candidate assesses.

Conceptually:

```
Challenge Candidate
        ↓
Challenge–Atom linking
        ↓
Knowledge Atom
```

If the assessment concerns a relationship between independent Knowledge Atoms, the relationship itself must be represented as a `relation` Atom, and the Challenge Candidate can be linked to that relation Atom.

## Source Provenance

A source-derived Challenge Candidate should retain enough provenance to identify where the task came from.

At minimum, provenance should allow the system to identify the source and the location of the extracted task.

For example:

```yaml
source:
  source_id: destination-c1-c2
  segment_id: ...
```

More precise item-level provenance may be needed when several tasks occur in the same Segment.

## Candidate Status

Challenge Extraction produces Challenge Candidates rather than immediately producing approved Challenges.

A Candidate may require review for:

- extraction accuracy;
- completeness;
- answer information;
- evaluation feasibility;
- appropriate extraction boundary;
- later Challenge–Atom linking.

The Candidate lifecycle is a separate concern from the extraction process itself.

## Scope

This document focuses on the extraction problem.

It does not yet define:

- the complete Challenge Candidate schema;
- the complete set of Challenge forms;
- Challenge–Atom linking rules;
- answer and evaluation schemas;
- Candidate review workflow;
- Challenge storage;
- learner performance;
- adaptive Challenge selection.
